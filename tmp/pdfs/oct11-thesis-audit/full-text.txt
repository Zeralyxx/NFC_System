11 TAGUIG CITY UNIVERSITY ABSTRACT Campus student verification and event attendance require reliable credential checks and traceable records. Paper-based attendance and reliance on a single credential can leave identity verification separate from recordkeeping. This study addressed the need to combine configurable credential validation, attendance recording, and monitoring within one workflow. A quantitative developmental and descriptive-evaluative design produced a WinUI 3 prototype integrating an ESP32 and PN532 NFC reader, PIN authentication, camera-based QR validation, local MySQL storage, and Firebase Firestore synchronization. Operators selected Fast, Standard, or High-Security modes, with QR providing an additional credential-integrity check. Evaluation included 80 proposed-system survey respondents, 70 separate manual-process student respondents, and controlled observation of 70 participants completing 210 successful entry trials across three modes. Mean internal latency was 11.49, 57.37, and 54.06 milliseconds for Fast, Standard, and High-Security modes; recorded Standard PIN and High-Security PIN/QR interaction averaged 2.505 and 5.799 seconds. Observed credential-decision accuracy was 100% (222/222) under researcher-labelled controlled conditions, while overall proposed-system survey means were 3.74 for students, 3.63 for security personnel, and 3.81 for administrative respondents, all Highly Satisfactory. Proposed-system student ratings exceeded manual-process ratings (3.742 versus 2.284), Welch t(89.08) = 15.12, p < .001; however, differing timing boundaries prevented a matched complete-task speed comparison.

18 TAGUIG CITY UNIVERSITY CHAPTER 1 THE PROBLEM AND ITS BACKGROUND Project Context As educational institutions adapt to the digital era, traditional manual campus management (relying on visual ID card checks at entry gates and paper-based sign-in sheets at events) has proven inefficient, error-prone, and insecure. Visual inspection allows borrowed, lost, or outdated IDs to pass unverified, while paper sign-ins create severe queue bottlenecks, invite proxy attendance, and fail to enforce real-time restricted event lists. Automated identification systems have been shown to improve verification accuracy and reduce manual processing errors (Rashid, 2024), and while automated single-factor systems (such as standalone NFC or RFID) improve entry speed, they introduce significant security vulnerabilities. Possession of a physical NFC credential alone does not guarantee the holder's true identity, as NFC UIDs can be easily borrowed, shared, or cloned (El Gaabouri et al., 2023; Mohammed et al., 2023). Furthermore, relying on security personnel to manually validate every individual digital transaction creates operational bottlenecks during high-traffic periods and conflicts with their primary responsibility of enforcing physical security. To address these vulnerabilities, this study develops a prototype for a Risk-Based Two-Factor Student Verification and Event Attendance Management System. The architecture integrates Near Field Communication (NFC) as a primary possession factor, Personal Identification Number (PIN) authentication as a knowledge factor, and Quick Response (QR) credential validation as a credential integrity validation to cross-check physical IDs against

===== PDF PAGE 19 =====
19 TAGUIG CITY UNIVERSITY database records to detect cloned tags. The system also incorporates a decentralized, student-facing web portal for out-of-band email OTP PIN resets, ensuring autonomous credential recovery without burdening administrators. To balance security with operational efficiency, the system applies dynamic verification modes configurable by security personnel, event organizers, or administrators: Fast Mode (NFC only) for low-risk, high-throughput routine entry; Standard Mode (NFC + PIN) for routine identity assurance; and High-Security Mode (NFC + PIN + QR) for restricted events. Credentials already flagged in the system, such as those marked inactive, expelled, or suspicious, are denied immediately regardless of the active mode. Ultimately, this framework shifts campus security from manual, transaction-by-transaction approval to an automated, alert-driven monitoring approach, providing a faster, more secure, and audit-ready solution for modern university environments. Purpose and Description The purpose of this study is to design and develop a risk-based, two-factor verification system prototype that strengthens campus security and identity verification processes through Near Field Communication (NFC) technology, Personal Identification Number (PIN) authentication, and QR credential validation. By replacing single-factor identification methods, the proposed system aims to provide a faster, more secure, and data-driven approach to validating individuals entering university facilities, particularly by preventing unauthorized access through borrowed, lost, or cloned credentials.

The framework presents how the proposed risk-based two-factor student verification and event attendance management system uses NFC technology, PIN authentication, and QR credential validation to support adaptive, multi-layer verification and attendance monitoring. The input consists of student identification data, including NFC-enabled credentials (UID), QR-coded student IDs, assigned PIN codes, enrollment status, photographs, academic details such as College, Section, and Year Level, and a temporary-credential flag for students issued interim NFC stickers or paper QR credentials. 27 TAGUIG CITY UNIVERSITY Limitations While the proposed Risk-Based Two-Factor Student Verification and Event Attendance Management System introduces a modernized, multi-layered approach to campus security, certain technical, operational, and methodological constraints define the boundaries of this research. The study focuses on prototype development and controlled evaluation, with limitations related to authentication methods, credential requirements, operational scale, security resilience, hardware conditions, and respondent coverage. ● Authentication Scope: The study is restricted to NFC, PIN, and QR-based verification methods and does not incorporate biometric mechanisms such as facial recognition or fingerprint scanning due to hardware costs, processing complexity, and data privacy considerations. ● Credential Requirements: Users must possess a compatible NFC-enabled identification card or an administrator-issued temporary credential to be processed by the automated terminal. Identity confirmation before a temporary credential is issued is performed manually by administration staff and falls outside the automated scope of the system. Test NFC stickers, simulated QR codes, and test accounts are used during prototype evaluation instead of live institutional records. ● Operational Scale: The system is designed primarily for campus entry points and large-scale institutional events rather than classroom-level attendance monitoring, where manual tracking may still be more practical. The study is limited to prototype evaluation under controlled conditions and does not involve full-scale university-wide deployment.

E.2 Technical Hurdles Resolved During execution, several theoretical designs were adapted to overcome technical constraints. The most significant hurdles and their engineered resolutions are detailed below: ● Offline Shadow Cache State Desynchronization: ○ Challenge: The system initially suffered from severe race conditions during intermittent network outages. If a student entered while offline, the local cache recognized them as "INSIDE", but the delayed cloud sync caused the master database to retain an "OUTSIDE" state. When the network stabilized, stale cloud data would overwrite the local cache, triggering false "Anti-Tailgating" and "Irregular Exit" violations. ○ Resolution: A "Hybrid Cache Merge" architecture was developed within the VerificationEngine. The system was refactored to treat the local RAM shadow cache as the absolute, immutable source of physical truth. State updates (e.g., Entry/Exit, PIN lockouts) are now unconditionally executed locally in RAM first , independent of the asynchronous cloud queue. This ensures 100% state continuity and eliminates false rejections regardless of network fluctuations. ● Hardware Port Exhaustion (COM Port Yielding):

===== PDF PAGE 215 =====
215 TAGUIG CITY UNIVERSITY ○ Challenge: The Windows operating system enforces exclusive, single-thread access to physical Serial (COM) ports. When the application transitioned from the Security Dashboard to the Fullscreen Verification Kiosk, the dashboard retained control of the ESP32 connection, resulting in fatal "Access Denied" software crashes. ○ Resolution: A dynamic hardware lifecycle manager was implemented. The application was programmed to actively yield (safely close and dispose) the COM port connection immediately prior to UI transitions. Hardware control is explicitly handed off to the active window and seamlessly reclaimed via background event listeners once the Kiosk is closed. ● Asynchronous UI Overlap Crashes (ContentDialog Threading): ○ Challenge: The Windows App SDK (WinUI 3) framework possesses a strict limitation where only one ContentDialog can render at a time. Simultaneous triggers such as a security alert overlapping with an administrative PIN prompt resulted in fatal COM exceptions. Arbitrary time delays (Task.Delay) proved unreliable under heavy processor loads. ○ Resolution: An asynchronous Dialog Queuing Helper (EnqueueDialogAsync) was engineered. This logic acts as a strict thread gatekeeper, mathematically halting secondary dialog executions in the background via asynchronous loops until the primary UI animation lifecycle is definitively closed, preventing software freezing. ● Temporal Precision and Strict-Mode Database Rejections:

===== PDF PAGE 216 =====
216 TAGUIG CITY UNIVERSITY ○ Challenge: During offline recovery, JSON log payloads were silently rejected by the local MySQL database due to strict DATETIME(3) schema constraints requiring exact millisecond precision. Furthermore, discrepancies between the local machine's clock and the database server resulted in out-of-order log entries. ○ Resolution: A mathematical time-sync engine (GetNetworkAdjustedTime) was integrated to calculate and apply clock-skew offsets against the server upon launch. Additionally, all JSON serialization scripts were refactored to enforce strict .fff millisecond string formatting, ensuring atomic data integrity during cloud-to-local recovery processes.
